Ce que je mets en place

Une chaîne CI/CD sécurisée, de bout en bout

Le pipeline que je construis dans mon laboratoire. Chaque étape a un rôle précis, et la sécurité intervient avant que le code n'atteigne le cluster.

pipeline #482 · dépôt oule · branche main · commit a3f9c1e · feat: ajout du service de commandes en cours
sourceGitea
orchestrationJenkins
testsJaCoCo + PIT
sécurité du codeSonarQube
dépendancesOWASP Dependency-Check
packagingDocker
registre sécuriséHarbor + Trivy
exécutionKubernetes

Chaque contrôle joue un rôle distinct : les tests vérifient que le code fonctionne, SonarQube repère les failles dans le code source, OWASP Dependency-Check signale les bibliothèques vulnérables pour qu'elles soient corrigées avant la construction de l'image, et Trivy détecte les vulnérabilités connues dans l'image finale. Ce pipeline continue d'évoluer au fil de mes apprentissages.

Approche

La boucle DevSecOps

La sécurité n'est pas une étape finale : elle accompagne chaque phase du cycle. Voici les outils que j'utilise à chacune.

  • planChoix d'architecture : outils de CI séparés du cluster applicatif.
  • codeDépôt Git auto-hébergé sur Gitea.
  • buildPipelines Jenkins et images Docker.
  • testJaCoCo, PIT, SonarQube et OWASP Dependency-Check.
  • releasePublication sur Harbor, analyse par Trivy.
  • deployKubernetes : Ingress, StatefulSet, RBAC et Secrets.
  • operateBastions Guacamole et Teleport, sauvegardes Bacula.
  • monitorWazuh, Centreon et Kibana.

k8s-portfolio-app

Une API Flask connectée à Redis, conteneurisée puis déployée sur Kubernetes en appliquant les bonnes pratiques de sécurité.
